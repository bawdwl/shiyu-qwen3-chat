# 首轮 RoleLLM 方法适配 LoRA 实验记录

日期：2026-10-26。当前状态：真实完整训练与8题开发对照完成；开发质量门槛未通过，不作为推荐模型；最终30题未运行。

## 本轮实际做了什么

使用 Qwen3-1.7B 固定版本与 Hugging Face PEFT，按逐条角色档案进行多角色 LoRA SFT。参考 RoleLLM 的角色条件化方法及 Character-LLM 的情境构造思想，使用项目训练循环，不宣称原论文完整复现。基础模型冻结，只训练约872万LoRA参数（约0.50%）。

数据、拆分与局限见[数据冻结记录](首轮角色条件化LoRA数据冻结记录.md)。这是52段原创训练对话加3条众包问答的小规模实验，不能将其包装成充分覆盖真实聊天分布的大数据训练。

## 候选选择与质量检查

按冻结计划，先以验证loss选最终Adapter（4.77低于半轮5.65），随后检查8道开发题。此时只有暂定候选，没有最终推荐模型。基础模型8题11轮原始生成已保存，其中4轮达到192-token上限，无空答。

基础模型开发诊断已发现：虚构物件从花瓶变成陶盘；声称实际看见用户的新鞋；用户明确道晚安时仍继续邀请聊天。这些是AI阅读开发回答发现的具体案例，不是人工评分或整体正确率。

## 评测协议纠正（最终测试运行之前）

初步开发生成使用了贪心解码。复核下载的官方Qwen3 README发现，非思考模式建议temperature0.7/top_p0.8/top_k20/min_p0；因此不直接把初步重复或生硬现象当作微调质量结论。原始greedy开发记录保留，作为该设置下的诊断。

新增 `outputs/rolechat-release-frozen-20261026-v2/`，仅更换生成协议为官方建议采样，每题每轮重设配对seed；训练/验证、开发问题、最终30题及其哈希均不改变。v1目录不修改，v2清单记录父清单哈希。训练仍是v1冻结数据产物，不重新训练。后续正式比较统一使用v2；不得将两种解码条件的答案混算成LoRA收益。一次配对随机种子仍不是多种子稳健性证明。

基础模型全部11个文件重新计算哈希，与原始下载清单一致；核验记录在训练目录 `base-integrity.json`，这是本地完整性核验而非新一次上游认证。

开发生成的输入是单独给出的角色卡，基础模型和LoRA完全相同；没有网页完整角色提示编排、世界书、摘要或记忆注入。这用于检查简化角色条件下的模型表现，不能直接代表拾语网页的整体体验。最终测试的角色说明也按冻结文件使用，避免事后加提示词来归功于LoRA。

## 完整开发对照结论（采样协议v2）

完整原始回答见[开发题完整对照](首轮LoRA开发题完整对照.md)。以下为AI诊断，不是作者盲评，也不是外部基准分数。两边同一角色卡、问题、采样参数、每轮配对seed；不混用贪心诊断结果。

| 观察项 | 基础模型 | LoRA | 能说明什么 |
|---|---|---|---|
| 8题、11轮生成 | 完成 | 完成 | Adapter重载与生成流程可用 |
| 达到192-token上限 | 5轮 | 0轮 | 这批输出更少触及上限，不等于内容更正确 |
| 空答 | 0 | 0 | 只覆盖本批短对话，不能保证全场景稳定 |
| 生成token总数 | 1784 | 1181 | 输出长度不同，不能用总耗时证明推理加速 |
| 算术找零、Python空列表示例 | 主要答案正确 | 主要答案正确 | 两道开发题无明显核心答案退化，不代表通用能力保持已充分验证 |
| 自创物件承接 | 保留茶壶 | 保留陶杯 | 采样条件下双方均沿用各自物件，不能把先前贪心条件的花瓶/陶盘失败混算为本轮提升 |
| 用户只想抱怨、不求补救 | 仍引导补救 | 仍给补救，且把角色职业套给用户 | 明确意愿遵循未解决，存在角色串位 |
| 最终约见时间 | 长篇无关内容 | 提及正确时间但仍加骑车安排与追问 | 干扰和答非所问仍存在 |
| 不知道用户手中书名 | 承认不知道后仍猜测 | 乱猜、声称看过封面、重复粗话 | 现实信息边界失败，LoRA有明显负面案例 |

**决定：保留为失败/未达标的适配实验，不替换网页默认模型，不合并转MNN，不作为“质量提升模型”上传。** 最终测试集继续冻结，避免用它反复调整到分数好看。没有运行第二轮，也没有用最终题挑选候选。

## 下一步聚焦的问题

先核对并统一训练与推理的角色提示结构：训练包含共同规则加角色卡，而当前开发探测只给独立角色卡。两模型的开发条件相同，但它不等于产品完整提示。下一项应在独立开发条件中给双方同样的完整角色提示，区分提示条件不足与模型适配不足，再决定是否增加数据或训练预算；不能把改提示带来的改善记成LoRA收益。

同时，本轮只有5177个训练监督token、21步，语料量与多样性都有限。不能仅据一次loss下降或几条失败认定具体原因，更不能直接断言增加轮数就能解决。训练链路的验证已经完成，质量改善仍需后续证据。

补充工程验证：冻结支撑文件（评测、开发、协议、审核记录）防篡改测试已加入，相关48项测试通过；构建、评测、对照渲染脚本实际运行，原模型文件本地哈希核验通过。

## 后续完整提示控制已完成

两边恢复训练时的共同规则后，基座输出上限触发从5轮降到0轮，LoRA仍为0；提示与微调作用已分开。但LoRA仍忽略意愿、虚构用户现实书名，算术开发题三种子复查基座3次正确、LoRA1次正确（仅此题，不是总体准确率）。该Adapter继续不推荐。详见[完整提示控制结论](完整角色提示控制实验结论.md)。未重新训练，最终题未运行。
