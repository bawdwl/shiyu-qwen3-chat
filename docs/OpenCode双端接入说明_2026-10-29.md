# OpenCode Go 双端接入说明

更新：2026-10-30

## 当前 Provider 结构

| Provider | 用途 | 默认模型 | 凭证 |
|---|---|---|---|
| OpenCode Go | 默认聊天与视觉 | `deepseek-v4.1-flash` | 独立 `opencode_api_key` |
| DeepSeek | 兼容与备用 | `deepseek-flash` | 原有 `deepseek_api_key` |
| 本地 Qwen | 本地兼容入口 | Qwen3-1.7B | 本地权重 |

网页和 Android 在设置中可切换 OpenCode Go 或 DeepSeek。两者保留各自的 API Key，不会互相覆盖。千问图片生成 API 与聊天 Provider 独立。

## OpenCode Go 接口

```text
Base URL: https://opencode.ai/zen/go/v1
Path: /chat/completions
Model: deepseek-v4.1-flash
Authorization: Bearer <OpenCode Go API Key>
User-Agent: shiyu-chat/0.9.4
x-opencode-session: <当前角色会话的稳定标识>
```

请求格式与 OpenAI Chat Completions 兼容。普通聊天关闭 Thinking，流式请求使用 `stream_options.include_usage`。

实测并通过：

- 非流式文本；
- SSE 流式分块和 `[DONE]`；
- `response_format: {"type":"json_object"}`；
- `image_url` 图片输入；
- 标准 usage 与 OpenCode 返回的 `opencode.billing_source`、`list_cost`、`allowance`。

## 网页实现

- `src/providers.py` 的 `OpenCodeProvider` 独立实现认证、请求头和额度元数据解析。
- `PUT /settings/opencode-key` 与 `DELETE /settings/opencode-key` 管理独立 Key。
- `/characters/{id}/conversation?provider=opencode` 会切换该角色唯一的持续会话 Provider，并保留历史消息。
- 普通聊天、角色生成、头像提示词和结构化记忆提取均携带稳定的 OpenCode 会话标识。
- OpenCode 返回的 allowance/cost 会进入本次 metrics；应用原有的每日 Token 限额仍单独执行。
- PC 端已接入 FTS5、本地 BGE、事实有效期、统一记忆排序，以及受证据约束的内部心情和关系状态。后台状态提取与自动记忆共用一次任务和独立预算。

## Android 实现

- `OpenCodeClient` 独立于原 `DeepSeekClient`。
- API Key 使用 Android Keystore/EncryptedSharedPreferences。
- `cloud_provider` 偏好决定当前状态；默认 `opencode`。
- 设置页分别提供 OpenCode Go 和 DeepSeek Key 输入以及 Provider 切换。
- 聊天、角色生成和结构化记忆提取都使用当前 Provider。
- `0.7.0` 曾在一加 Ace 5 覆盖安装并完成真机聊天；`0.8.0` 已完成 Room 4→5 真机覆盖升级，真实 OpenCode 自动记忆新增、更正、重启后追问和删除墓碑链路通过。
- `0.9.4` 已同步 FTS4、事实有效期、统一上下文、内部状态、自然单条角色回复和主动开场；四段式 UI 已撤销。一加 Ace 5 已完成覆盖升级、数据库迁移、FTS4 回填、单气泡显示和 MediaPipe 本地头像生成验收；0.9.4 同时修复角色编辑草稿串角色并加入中文外貌描述。云端生图入口保留。

## 使用边界

OpenCode 官方说明该服务主要面向 OpenCode 和类似编码 Agent，并会监控影响其他用户体验的异常流量。拾语的虚拟角色聊天属于非编码请求，需要遵守 OpenCode Go 当时有效的使用规则；DeepSeek 备用 Provider 可继续用于回退。
