# 拾语 PC 端：记忆检索与内部状态

更新：2026-10-30

## 范围

本文件记录 PC 网页端第一至第三阶段的实现与验收。四段式表现层后来在双端实现又因作者体验不佳而撤销，当前规则见[自然角色回复与主动开场](自然角色回复与主动开场_2026-10-30.md)。

1. 自动长期记忆闭环；
2. 精确、全文和语义检索及统一上下文；
3. 心情、关系和边界等内部状态。

LoRA、MNN、GPTQ、vLLM、TensorRT-LLM 不属于本轮范围。

## 产品原则

- 用户聊天时不确认单条记忆。
- 模型只提出事实和状态事件，程序负责引文、主体、时间和权限校验。
- 固定角色卡、核心人格和作者设定优先于普通对话。
- 用户当前消息优先于已存记忆；明确更正由后台保存新旧版本。
- 情绪和关系使用数值做内部计算；提示词只使用自然语言，回复和界面不默认展示数值记录。
- 状态不占用正常聊天额度；后台记忆、状态使用独立预算。
- 内部状态不阻塞主回答。回答保存后才进入持久后台任务。

## P0：自动记忆

已有并继续保留的行为：

- 聊天的用户和助手消息原子保存后创建或合并 `memory_jobs`。
- 后台 worker 按 24 条一批推进游标；只有实际处理到的消息才标记完成。
- 支持 `add / merge / supersede / contested / ignore`。
- 明确更正保留旧值，当前查询只注入当前值；历史问法才加入旧值。
- 删除一个事实会删除整条历史链并写入墓碑。
- 同一旧原话再次被扫描不能复活；用户后来明确重述时可以建立新记录。
- 网页和 Android 保留各自已经验收的 P0 规则。

## P1：检索与上下文

PC 端结构化记忆库新增：

- SQLite FTS5 `trigram` 全文索引；
- `valid_from / valid_to` 观察有效期；
- `importance / confidence` 排序信号；
- 本地 `BAAI/bge-small-zh-v1.5` 512 维语义向量缓存；
- FTS、词法、短语、BGE 余弦、时间和来源可信度混合排序；
- 结构化事实、会话摘要和旧原话的单一上下文竞争与字符预算；
- 被结构化事实覆盖的旧原话不再重复注入。

BGE 在独立子进程中运行。这样既隔离 PyTorch/OpenMP 原生库，也避免在 FastAPI 主进程重复加载模型。模型缺失或运行失败时，检索自动退回 FTS5 和确定性词法匹配，聊天仍可继续。

模型下载：

```powershell
python scripts/fetch_embedding_model.py
```

默认目录为 `outputs/models/bge-small-zh-v1.5/`，不进入 Git。当前固定 revision 为 `7999e1d3359715c523056ef9478215996d62a620`，文件哈希记录在 `model_source.json`；模型卡标注 MIT，最终发布前仍以模型仓库许可证原文为准。

不启动网页也可以检查真实语义检索：

```powershell
python scripts/smoke_bge_memory.py
```

## P2：内部心情与关系

新增数据：

- `character_states`：心情效价、唤醒度、自然语言标签和更新时间；
- `relationship_states`：熟悉度、信任、温暖、关系阶段和更新时间；
- `state_transitions`：去重键、来源任务、消息范围、事件类型、重要度、前后状态、变化量、原因和逐字证据。

用户边界仍以状态为 `active` 的结构化事实为主，状态快照从这些事实生成；删除边界事实后，下一次状态快照不会再带出它。

后台只在有证据的显著事件后尝试更新。程序负责：

- 拒绝引文或说话人不匹配的事件；
- 实测低重要度事件不改变状态；
- 对单次心情和关系变化限幅；
- 心情随时间恢复，温暖缓慢回落到中性；
- 用户命令“你必须完全信任我”等不能直接提高信任；
- 冲突和修复可以改变关系阶段；
- 边界可以来自带 `boundary` 的关键词事实或显式边界事件；
- 核心人物档案不被状态模块改写。

聊天开始时冻结一份内部状态快照。系统提示只加入自然语言，例如：

```text
你此刻的心情：有些低落。
你与用户的关系阶段：逐渐熟悉。
你还没有建立很深的信任。
不要展示内部数值、分析过程、事件类型或“好感度”。
```

本轮先把状态保存、更新和提示投影做稳。状态数字只由程序计算，不接受模型直接填写；四段式展示实验随后因破坏自然聊天而撤销，当前状态只进入内部提示，不在回复中显示。成长、反思和 Live2D 仍未实现。

## 主要代码

- `src/structured_memory.py`：持久任务、事实状态、FTS5、语义排序和统一上下文。
- `src/memory_embeddings.py`：BGE 子进程客户端。
- `src/memory_embedding_worker.py`：隔离的 BGE 推理进程。
- `src/internal_state.py`：确定性状态限幅、衰减、阶段、证据和自然语言投影。
- `src/backend.py`：自动任务、状态事件、冻结提示快照和健康状态。
- `src/prompt_pipeline.py`：P1 统一记忆接管后避免重复注入旧摘要。

## 验收

确定性 PC 验收：

- Python 全量 362 项通过；
- FTS5 可用且能索引中文三元组；
- BGE 真实模型在独立进程中返回 512 维向量；一条不包含“面试”等直接词面的查询以 0.35336 语义分选中了“面试改到周五”，FTS 与词法分数均为 0，证明语义召回路径实际生效；
- 本次冒烟中，首次查询约 4.57 秒（含子进程和模型加载），同一查询暖启动约 1.13 毫秒；这不是不同硬件或不同模型的基准排名；
- 新自然对话的 11 个检查点均能在检索前 4 项中找到目标来源；
- 当前状态问题没有命中已失效旧值，旧事实泄漏率为 0；
- 单次统一上下文平均约 195 个字符，未把所有记忆一次性注入；
- 重复事实执行合并；
- 删除事实的原话重放被墓碑阻止；
- 显著状态事件可更新，低重要度事件被忽略；
- 状态只以自然语言进入提示词，没有内部数值或事件类型泄漏；
- 明确边界进入关系提示。
- 更新后的真实 PC 服务在现有结构化记忆库上返回 `fts5_lexical_bge`；一次针对性提示构建选入 8 条事实且命中目标来源，共使用 238 字符，内部状态描述存在且不含数字；20 条活动事实已生成向量缓存，数据库完整性检查为 `ok`。

## 当前限制

- 本轮确定性测试验证存储、更新、检索和提示投影，不替代真实云端模型对每句话的提取准确率。
- 当前本机 OpenCode Key 在真实调用时返回无权限，因此本轮没有把新的状态提取提示词冒充为真实 API 质量结果；需要有效 Key 后再做一轮新对话。
- Android 已同步 FTS4、事实有效期、统一检索预算和 P2 内部状态；因手机未连接，Room 6→8 迁移仍待真机验收。
- 状态数值和阈值还需要作者在真实长对话中检验自然度；不达标时可以直接移除状态模块。
- 反思、长期观察和角色成长弧线尚未实现。
