# 自动长期记忆第一阶段实现与验收

更新：2026-10-30

## 范围

网页端先完成实现与验证，随后按同一规则迁移到 Android。目标是让用户在两端正常聊天中都不需要确认记忆，同时保留可追溯证据、自动更正、删除保护和后台成本上限。

本文的主体是 P0 自动记忆。PC 端随后加入了 P1 FTS5/BGE 检索和 P2 内部心情/关系状态，详见[PC 记忆检索与内部状态](PC记忆检索与内部状态_2026-10-30.md)。Android 已同步 P1 的 FTS4/统一预算和 P2 状态规则。四段式表现层试验已撤销，当前双端恢复单条自然回复，状态只进入内部提示。反思与成长仍未实现。

## 已实现流程

1. 网页完整保存一轮用户消息和助手回答。
2. 保存成功后创建或合并该角色的持久 `memory_job`，不会在网络请求期间占用聊天生成锁。
3. 后台 worker 在短暂停顿后读取最近最多 24 条对话，并放入最多 40 条当前事实。
4. 模型返回带原始消息编号和逐字引文的候选事实。
5. 程序验证说话人、原文、主体、值和日期，然后自动执行：
   - `add`：新增事实；
   - `merge`：同一事实和值合并来源；
   - `supersede`：较新的明确更正替代旧值；
   - `contested`：冲突但证据不足时不进入当前上下文；
   - `ignore`：寒暄、推测或没有长期价值的信息不保存。
6. 后台记录已经处理到的消息位置，下一任务不会反复提交同一批旧候选。
7. 用户删除记录时创建墓碑。同一旧消息和同一值不会被再次自动提取；用户后来在新消息中重新明确说明时可以重新建立。
8. 删除、替换、疑义和当前事实都保留来源与动作原因，供记忆页检查。

## 事实键和冲突

- 事实键统一使用英文小写。
- `day`、`date`、`when` 会归一为 `time`。
- `location`、`city` 会归一为 `place`。
- `job`、`occupation` 会归一为 `work`。
- `current.*`、`profile.*`、`item.*` 会按主体改为 `user.*`、`character.*` 或 `shared.*`。
- 模型给出的目标记录必须属于同一角色、同一主体和兼容类型；无效目标会回退到程序匹配，不能直接修改其他角色记忆。
- 旧值和更正后新值同时保留。普通问题只读取当前值，历史问题才带入明确标记的历史旧值。

## 上下文统一

网页仍保留原会话原文摘录，但结构化事实成为更高优先级的长期记忆：

- 被当前结构化事实覆盖的原文摘录不再重复注入；
- 已替代历史值的来源仍由结构化替代链负责；
- 已删除事实的来源继续从旧摘录中排除，避免卸载后从另一套记忆复活；
- 当前用户消息始终高于已存长期记忆。若本轮明确更正，回答以本轮消息为准，后台再持久化变化。

## 成本与可靠性

- 每个角色每日独立后台预算：30,000 Token。
- 后台用量与正常聊天用量分开统计。
- 每条后台任务使用固定 job id 幂等记账，重试不会重复累计同一批实际 token。
- 普通聊天不等待后台记忆模型。
- 任务状态为 queued、running、completed、failed。
- 服务重启后未完成任务仍保留；超过租约的 running 任务可以重新领取。
- 未配置云端 Key、额度耗尽等可恢复情况进入延后，不消耗普通重试次数。
- 模型错误或无效输出有有限重试，达到上限后标记 failed，聊天和已有记忆不受影响。
- SQLite 使用 WAL、busy timeout 和单 worker 短事务；模型网络请求在事务外执行。
- 网页和 temp DB 都验证了后台任务不会占住聊天生成锁。

## 当前限制

- 事实识别仍依赖云端模型；程序只能校验证据表面一致性，不能完全证明摘要语义正确。
- PC 端已接入 FTS5、BGE 向量和统一排序；Android 已接入 FTS4、事实有效期、重要度/可信度和统一排序，可选语义接口在模型缺失时回退。
- 复杂相对日期、计划完成、事件有效期和跨事件关系仍是下一阶段。
- 后台预算按自然日限制，但实际请求可能因一次任务估算误差少量超过预留值。
- 敏感信息的专门保存、检索和删除策略仍需单独设计。
- 网页与 Android 仍各自存储，不自动同步。
- PC 与 Android 均已实现内部心情、熟悉、信任、温暖、关系和边界状态；成长和反思仍属于后续阶段。
- 当前一加 ColorOS 15 在应用进程被结束后会保留并尝试执行 JobScheduler 请求，但 WorkManager 服务重新绑定失败；重新打开应用后任务完成。不能把跨进程恢复表述为所有 Android 设备都能立即后台处理。

## Android P1：检索与事实有效期（0.9.0）

更新：2026-10-30

Android 已从原有 P0 词法检索同步到 P1，同时保留此前完成的 P2 内部状态规则：

- Room schema 从 6 升级到 7；
- `structured_memories` 新增 `validFrom`、`validTo`、`importance`、`confidence` 和 `searchTokens`；
- 新当前事实写入 `validFrom`，被更正或删除的事实写入 `validTo`；
- 同一事实再次出现时保留原有效期、提高置信度并保留较高重要度；
- 普通问题只读取 `active` 事实，只有“原来、之前、以前”等历史问法才加入 `superseded`，`deleted` 永不进入对话上下文；
- 角色范围在 DAO 查询和统一排序两层校验。

中文检索使用 Android 通用支持的 FTS4。程序把中文切成单字、二元组和三元组，把英文切为单词，再由触发器同步 `structured_memory_fts`。旧数据库启动后会自动补齐已有行的 `searchTokens`；缺失 FTS 表或查询失败时自动回退到确定性词法召回，不阻塞聊天。

用户输入中的引号、通配符和布尔词不会直接成为 FTS 语法：查询器只接受程序分词产生的 token，对每个 token 加引号，并将查询限制为最多 64 个去重 token。

本轮统一上下文按以下信号竞争：

- FTS4；
- 中英文词面重合；
- 连续短语；
- 事实重要度和置信度；
- 来源类型；
- 观察顺序；
- 可选语义分数。

结构化事实优先于同相关度的旧原话；两类来源共享最多 8 条事实、4 条摘录和约 1,600 字符预算，并去除规范化后重复的内容。Android 未打包约 95 MB 的 BGE/ONNX 模型，因此当前默认模式是 `fts4_lexical`；已保留 `MemorySemanticProvider` 接口，未来可接入量化端侧向量模型，无模型或模型失败时仍可稳定聊天。
