# 拾语角色卡与世界书功能说明

## 2026-10-27 更新：提示组装与同会话记忆初版

追加用户体验修复：角色“林浩”的开场情境曾每轮注入，示例对话也可能被模型照搬；历史中连续重复的回答又进一步促成循环。自定义角色的开场情境现在只在第一轮使用；示例默认不注入，用户可在角色编辑器选择仅开场参考。若最近历史的多条回复重复了至少两句相同话术，发送给模型前只省略重复句，数据库原始聊天保持原样；询问原话或要求重述时跳过该处理。一次同历史、各一次采样的本机对照中，旧提示重复便利店内容，新提示接续原神话题，但仍有连续追问，不能保证以后不重复或整体自然度已提高。原输出留在 `outputs/role-continuity-diagnosis-20261027.json`。

作者要求先完成提示词、角色和记忆的体验验收，再进入LoRA；本节覆盖下文有关“摘要尚未实现”等旧描述。普通与流式聊天现共用 `prompt_pipeline.py`：角色/规则、最近历史触发的世界书、当前会话摘要及话题召回原文、最新消息；自定义示例只注入一次。世界书仍是最多4条的关键词匹配，支持条目优先级和启用/禁用，不是完整SillyTavern World Info。

角色卡生成分两次模型调用：先生成人物草稿，再补充开场情境、人物目标、世界书和示例。第二步格式错误时保留第一步草稿并提示；自动生成内容仍需作者检查。角色可以配置采样参数，默认沿用全局设置；该预设不是模型自动判断出来的最佳值。

默认在线推理输入预算4096 token。上下文达到75%预算，且有至少4轮较早对话、仍保留最近4轮原文时，调用本机模型从早期消息选择可核验的原文摘录（通常每批最多6轮），仅保存在当前会话；同时可按当前话题从已整理的同会话原文中找回相关问答。该方法是有来源的摘录和关键词召回，不是完整的语义摘要、无损压缩或长期记忆。模型可能遗漏重点、选错片段或答错；较早单轮超过整理批次大小时不会推进摘要，会显示提示，原文仍在数据库。

聊天页“会话记忆”可以查看原文摘录、取消选择、添加修订、暂停自动整理和恢复上一版；取消的消息不再从早期历史召回。会话清空和删除同时清除其摘要，新会话从空白开始。提示预览按当前输入框预览，自动摘要生成后实际内容可能不同；预览并非完整的未来生成保证。

新增自动整理会额外占用本机模型时间，摘录只验证是否逐字出现在原消息，不能保证被选中的信息有用或角色最终一定遵循。短期实时语音、跨会话记忆和SillyTavern插件均未集成。

## 目标与取舍

拾语借鉴 SillyTavern 的角色卡、关键词世界书和上下文编排思路，但保留拾语自己的网页和本地模型调用流程。本轮没有把 SillyTavern 页面嵌入拾语，也没有复用其前端源码。已有 `third_party/SillyTavern/` 作为固定版本的学习/对照材料保留；拾语启动和聊天不依赖它。

网页通过本机 FastAPI 请求角色生成与聊天，FastAPI 在同一进程内调用本地 Qwen 推理引擎。生成角色卡不会访问云端模型，也不会训练或修改 Qwen 权重。项目的 `/v1` OpenAI 兼容路由属于既有接口，本功能不经过酒馆 API。

## 角色创建流程

1. 作者给出关键词或一段背景，例如“海边小城的夜班电台主持人，喜欢听众点歌”。
2. 本地 Qwen 生成结构化 JSON 草稿：名称、简介、背景、性格、表达方式、用户关系、开场白、固定设定提议、世界书条目和少量示例对话。
3. 拾语检查字段类型和长度，把模型新编的具体事实统一标成“待确认”；作者输入原文单独保存在“创作前提”。
4. 作者在网页中修改草稿，并逐项把要长期固定的事实标成“确认”后保存。只有保存后的角色进入角色列表；模型生成内容本身不会自动写进角色库。
5. 新聊天使用该角色的角色卡。普通虚构细节可以在对话中即兴创作；应用不会把其他对话的即兴细节带入新聊天。

角色创建提示刻意限制输出规模，不生成没有要求的玩家姓名、外貌、年龄、家庭或装备，也不一开始产出成万字世界观。用户给出的灵感是创作约束，模型扩写为草稿；若草稿与用户意图冲突，应由作者改正后再保存。

### 对话节奏与追问

角色卡里的“温柔、体贴、善于沟通”等性格词，容易让小参数模型学成“回应一句，再补一个问题”的陪聊模板。仅写“不要每轮反问”不够具体。因此运行提示明确规定：先回应当前内容，默认用陈述句收尾；答案完整就停止；只有确需澄清、用户要建议或当前话题需要对方选择时才问一个紧扣主题的问题。禁止在每轮末尾机械追加“你呢”“最近有什么有趣的事”“还有什么想聊的”“要不要一起”等泛化钩子。

这只是提示词约束，不是输出过滤器，也不能保证 Qwen3-1.7B 每次严格遵循。角色卡的关系和性格继续作为角色语境，但不意味着模型需要反复索取用户回应。若仍出现连续追问，应检查角色的“说话方式”、关系描述和示例对话是否暗示了相同模式，再用同一段自然聊天复测；不通过删除所有问句来换取表面合规。

## 世界书和提示词

角色卡主字段每轮加入系统提示。自定义世界书以“关键词 → 内容”的条目保存在同一张卡内。当前使用 Unicode 规范化后的大小写不敏感子串匹配；每轮最多追加命中数最多的 4 条启用条目，不命中时不追加内容。用户可以在角色卡编辑器中逐行修改：

```text
关键词1,关键词2｜条目标题｜条目内容
```

这是可解释的第一版关键词检索，不是语义向量检索，也没有正则、递归触发、世界书分组权重或酒馆完整的插入位置控制。应避免在关键词上使用过短的常见词，否则容易误触发；过长的段落放在世界书中也会抬高上下文开销。

保存后的角色卡可从聊天页“编辑角色卡”再次修改。角色卡以 JSON 存在本机 SQLite 中，不包含模型权重或外部服务凭证。

## 上下文与摘要现状

- 所有已完成的聊天轮次都保存在 SQLite。
- 超出推理上下文预算时，现有 `context_window.py` 按完整问答轮次裁掉较旧内容，完整原始记录仍留在数据库。当前预算默认 2048 token；实际输入也受模型上下文长度约束。
- 小满同聊记忆实验可以从已裁掉的回答中检索少量角色自述原话；它是单独的实验开关，不适用于全部角色，不能称为通用摘要系统。
- 自动摘要和摘要修订/回看 UI 尚未实现。本轮不把“裁剪历史”描述成“摘要”。

后续如做摘要，建议作为单独层：只总结模型输入窗口之外的旧完整轮次，摘要标记覆盖的源消息范围与更新时间；保留原文供查看和重建；清空会话同时清除摘要；新会话不共享摘要。先经固定多轮对话验证摘要没有混淆用户事实、角色自述、假设和玩笑，再启用自动刷新。它不会改写数据库里的原始消息。

## 测试与边界

接口测试覆盖生成结果校验、作者确认后保存、角色列表和会话关联、世界书按需注入以及删除后旧会话的明确错误处理。测试使用模拟模型输出，只证明代码路径正确，不证明本地 Qwen 每次都能返回完美 JSON，也不证明生成的角色文案质量。

本轮还用本地 Qwen3-1.7B 对“海边小城的夜班电台主持人”做过两次未保存的生成验证。第一次把应用名当成角色名，且示例回复只有名字；因此增加了品牌名碰撞修复和无效示例过滤。第二次生成出“海风”，开场白与名字一致，但示例仍为空。这说明生成接口能工作，不能说明角色文案已达到作者偏好；角色卡编辑器保留示例编辑，作者应检查、补充后再保存。

现阶段仍是 Windows 单机单用户工具。角色卡、对话和 SQLite 都是本地数据；暂未提供加密、账号同步或多用户隔离。不要将无鉴权的本地服务暴露在公网。项目尚未公开发布。
